00 — How to use

A design system for a campus marketplace.

Two files. tokens.css holds every value; components.css holds the kit. Set class="zl-ui" on <body> and compose from the semantic tokens. This page is the living specimen — switch the theme and the language in the sidebar and watch every component below follow.

!
What is official here, and what is not The colour values and the 60/30/10 balance come from Zhejiang University's published visual identity. The type families, the scale, the grid, the components and the entire dark theme are proposed extensions — not official ZJU specification. No seal, eagle or 浙江大学 wordmark is used anywhere in this system, and none may be added without written permission from the university.

The search action sits on the right. It is a real type="submit" button inside the field, not a decorative glyph — so the search runs on click as well as on Enter — separated from the input by a hairline, and filling the field's full 44×44 rather than floating at 36 inside it.

The search hint rolls. A native placeholder cannot be animated or hold markup, so this is an overlay: the prefix is fixed and the term cycles through eight values, two of them taking an so the article varies. Three things keep it from being a liability — it is aria-hidden, so a screen reader gets the field's real label instead of a name that changes every 2.4 seconds; it is pointer-events:none, so clicking it focuses the field beneath; and the input keeps placeholder=" " so :placeholder-shown still works, which is what hides the hint the instant anything is typed. prefers-reduced-motion stops the roll on the first term rather than blanking the field. The keyframes have one step per term, so the list length is load-bearing — a termCountProblems() guard in i18n.mjs fails loudly if a locale drifts to a different count.

The top of every page. The wordmark is real text set in the body typeface with an accent full stop — not an image, and emphatically not the ZJU seal. It stays sharp at any density, recolours with the theme, is selectable, and a screen reader simply reads it. This is the one component with a legal constraint attached, so it is specified here rather than left to a logo file someone might swap.

The disclaimer strip, in place. Navy 900 with white text — 15.32:1 — persistent on every page. It went neutral → Innovation Red → Navy 900; navy reads as institutional rather than as an alert, which is what a standing notice should do, and it leaves Innovation Red marking exactly one thing again. Note the hairline on its lower edge: navy against the Blue 800 header is only 1.51:1 and shares its hue, so without the seam the two bands merge into one dark mass.

03 — Spacing & layout

One 4px scale. Parents own the gaps.

Tokens follow Tailwind/shadcn numbering — the number is the multiple of 4px, so --zl-s-4 is 16px and --zl-s-6 is 24px. Every margin, padding and gap in the system is a token; there are no raw pixel values and no inline style="" in any view. Half steps (s-0-5, s-1-5, s-2-5, s-3-5) exist only for the insides of small controls.

Tabs

Renewed Removed by moderator

Tabs carry counts. On My listings the count is the whole point — you open the page to find out whether anything expired.

The chip row scrolls, and now says so. An arrow appears at each edge only when the track actually overflows in that direction — so on a short row neither shows, and at the start only the right one does. Each sits over a fade so chips slide out of view rather than being chopped. Swipe and trackpad scrolling are untouched: the buttons are enhancement over a plain overflow container, and they are rendered hidden so a reader without JavaScript gets exactly the behaviour that existed before.

Worth knowing: the hidden attribute only gets its display:none from the UA stylesheet, so any component rule that sets its own display silently defeats it. A base .zl-ui [hidden]{ display:none !important } makes the attribute mean what it says — three controls here had been staying visible because of it.

Every status badge carries a word or a mark as well as its colour. The verified badge is a tick and the words — colour alone is never the signal.

Three price states, and only one of them is a number. Free is a status rather than a price of zero, so it takes the success token — the reserved-meaning case earns it: an item that costs nothing is good news, and it is labelled in words either way.

Gallery / carousel

1 / 3

Photo: A. Photographer / Unsplash

The track scroll-snaps, so swipe works with no JavaScript at all — the arrows, thumbnails and counter are enhancement layered on top. Thumbnails stay visible rather than collapsing to dots, because what else is in the set is part of how a buyer decides whether to keep looking. A single-photo listing gets .zl-gallery--single and no chrome.

It wraps. Past the last photo the next arrow returns to the first, and back past the first goes to the last, so an arrow is never a dead end — there is no disabled state on either carousel. Crossing that seam jumps rather than scrolling smoothly: animating back across every photo reads as a rewind, not as a wrap. Steps inside the run stay smooth.

Cards carry their photos. The media box is a scroll-snapping track, so swipe works on touch with no JavaScript; arrows appear on hover (hidden entirely on touch, where swipe already does the job) and dots mark position. Every control sits above the card's stretched link and calls stopPropagation, so paging a photo never navigates to the listing. Both carousels hold their index in a variable rather than re-reading scrollLeft: mid-smooth-scroll that value still reports the old position, so two quick clicks would compute the same index and stall. The count badge and the favourite are inline SVG, not text glyphs — ▤ was a table character standing in for a photo icon, and ♡ has no weight control. The heart is stroked at 2.1 and fills from aria-pressed, so state no longer means swapping one character for another.

One hit area, one hover state. The card is an <article>; the title link stretches over the whole card with ::after, and the favourite button sits above it on its own layer. Baymard's product-list testing found 76% of sites leave users unsure what is clickable inside a list item — and the obvious shortcut, wrapping the card in an <a>, is invalid HTML the moment there is a button inside it, which is exactly what a favourite control is.

The media box is a fixed 4:3 with a placeholder colour, so the grid never reflows as photos load — that is the entire CLS budget spent in one decision. Listing photos are never duotoned. The guidelines' 15–20% blue overlay is for campus and editorial imagery; a buyer has to see the real colour of the thing they are buying, so the overlay stops at the marketing pages.

Search, filters, and the empty search.

The parts of the product that decide whether anyone finds anything. Every rule here comes from Baymard's product-list, search and mobile studies — see docs/ux-guidelines.md for the findings and how they were translated to a campus board.

Campus is a persistent browsing scope, carried in the header the way OLX carries its region: a map pin, a quiet Browsing line, and the place itself as the thing you read. No border — on a saturated header a pill around it competes with the real buttons. A native <select> lies invisibly on top, so the OS picker, keyboard behaviour and mobile wheel all come for free; the visible text is aria-hidden so the field is announced once, not twice.

Precedence. The header scope filters every page except search results. Search is seeded from it on arrival, but the moment the rail is used it wins — including when the user unticks every campus, which means "all", not "fall back to the header". The rail stamps f=1 on submit and that marker, rather than the presence of a value, is what signals it. Changing the header while on search clears the rail's campus state so the new scope visibly applies. Below 900px the rail collapses behind the Filter pill with its active count.

Labels in caption grey, values in body size, figures in mono so they align down the column. Share and report sit together as a matched pair of minor actions: one is a courtesy, the other a safety valve, and neither should compete with Message seller, so they share a single quiet style. The report control stays visible rather than buried in a menu. Share is rendered hidden and revealed by script — it needs either the Web Share API or the clipboard, so a button that silently fails is worse than no button; where a native share sheet exists it is used, otherwise the link is copied and the label confirms it for a moment.

Control shape

One rule keeps a filter row coherent: pill = choose from options (chips, sort, condition), rectangle = type a value (search, price), rectangle = perform an action (buttons) — and everything on the row is 44px tall regardless of family. Before this the chips were 44px and the sort select was 36px with a heavier border: the same job wearing two different appearances, which is what made the row look assembled rather than designed.

12 — The rules

Seven things that don't bend.

Do

Compose from semantic tokens — --zl-text, --zl-bg-raised. It is what makes dark mode cost nothing.

Don't

Write a raw hex in a component. That is a dark-mode bug that hasn't happened yet.

Do

Use red once per view, for the highest-priority action.

Don't

Use red for decoration, for a second button, or behind body text.

Do

Underline every link, always.

Don't

Signal anything with colour alone — status badges carry a word or a mark too.

Do

Show listing photos at their true colour.

Don't

Apply the blue duotone to listing photos. Editorial imagery only.

Do

Keep every tappable thing at 44px, and inputs at 16px.

Don't

Shrink inputs below 16px — iOS zooms the page on focus.

Do

Measure any colour you add, in both themes, before shipping it.

Don't

Trust that a colour "looks fine" on dark. Truth-Seeking Blue looks fine and measures 1.84.

Do

Set the wordmark in the body typeface, as real text.

Don't

Use the ZJU seal, the eagle, or the 浙江大学 wordmark. Not in the header, not in the footer, not in the favicon.

13 — Brand

WeZJUers

The name the community already uses for itself, which is the point: it reads as students speaking, not as the university speaking. Two assets with different jobs: the name is the logo, and a pair of message balloons is the app icon, for the places a name will not fit.

The mark

Two speech balloons, one answering the other, with the three dots of a reply being typed. The platform's front door is the Community, so the icon says the thing the product is for — people talking to each other — rather than spelling the name a second time. Solid, not outlined: at 16px an outline fills with its own background and the silhouette is all that survives, so the silhouette is what the mark is made of.

Traced from supplied artwork, not redrawn: marching squares over the bitmap for the five contours — two balloons and three dots — then Douglas–Peucker at ε 2.5 to drop the sampling noise, then Catmull–Rom cubics with corners above 48° held sharp so the tails stay pointed instead of being rounded away. That takes it from 3,668 sampled points to 93, and the whole mark to about 3KB. It fills 52 of the 64 grid and carries fill-rule="evenodd", which is what knocks the dots and the gap between the balloons out of the fill rather than painting them in the tile colour — so the mark works on any background, including one ink.

It is detailed for an icon. Two balloons, the gap between them and three dots is three levels of detail, and below about 24px they compress into one shape: measured, it reads cleanly at 24px and up, is soft at 20 and is a silhouette at 16. On a retina display a 16px favicon is rasterised at 32 device pixels and reads fine, so this mostly bites on older screens. Lives at app/public/favicon.svg, with icon-32.png for browsers that will not take an SVG favicon and icon-180.png for an iOS home screen. It is the app icon only — the logo is the name, and the two are never set side by side.

Wordmark

The name as one word, in the body face at 800, tracking −.035em. Real text, not an image: sharp at any density, costs nothing to download, selectable, readable by a screen reader, one CSS rule to restyle. No mark beside it and no spans inside it.

WeZJUers
WeZJUers

Joining the words is what fixed the junction. Set apart as “We ZJUers”, the acronym towered over the lowercase and the eye tripped at “Uers”; the fix then was to set ZJU at 90%. Closed up, that reduction reads as a rendering fault — the acronym visibly dips below the leading W — and it is not needed, because a capital already leads the word and the eye expects the capitals inside it. Camel case does the work, as it does in WeChat, PayPal and YouTube. One colour, one weight: the earlier wordmark tinted “We” pale blue, which on the blue header read as a disabled control rather than as emphasis.

Do

Keep the disclaimer strip above the header on every page. The name carries ZJU; the strip is what keeps it honest.

Don't

Set the wordmark as an image, or letterspace, outline, shadow or rotate it.

Do

Use the tile wherever a wordmark would be illegible — favicon, app icon, avatars.

Don't

Put the tile and the wordmark side by side. They say the same thing twice.

Do

Re-measure the ink after any change to the mark, and re-check it at 16px. A shape that survives there survives everywhere.

Don't

Add a second element to the tile — a letter, a full stop, a year. One mark is the whole point of having one.

Don't

Outline the balloon, or thin its tail. Both read fine at 96px and both disappear at 16.

Do

Write the name closed up, as one word, wherever it appears — header, title, docs, slides.
